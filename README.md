# 🎓 Бот расписания СПК

VK-бот, который следит за изменениями расписания Сургутского
политехнического колледжа и присылает уведомления в беседу группы.

Умеет:

- следить за расписанием вашей группы в автоматическом режиме;
- присылать изображение с таблицей расписания (как на сайте колледжа)
  для `/today`, `/tomorrow`, `/week`, `/nextweek`;
- присылать короткие уведомления об изменениях (замена преподавателя,
  кабинета, отмена пары, дистант) с подсветкой изменённых пар;
- при массовых изменениях — присылать полное расписание дня или всей недели;
- автоматически отправлять расписание следующей недели, как только
  колледж его выложит;
- работать автономно 24/7 в облаке.

## Как это работает

Бот обращается к двум эндпоинтам сайта колледжа:

- `/api/schedule/index` — справочники (группы, преподаватели,
  дисциплины, аудитории);
- `/api/schedule/schedule?date=<timestamp>` — расписание на дату.

Справочники кэшируются в SQLite на сутки. Расписание проверяется
по расписанию окон (см. [Расписание проверок](#расписание-проверок)),
сравнивается с предыдущим снимком в БД. Если что-то изменилось —
формируется изображение с таблицей расписания и отправляется в беседу ВК.

Изображение рисуется локально (Pillow), без внешних сервисов.
Хранится только PNG недели (для дедупликации); дневные PNG создаются
на лету во временной директории и удаляются после отправки.

## Архитектура

Проект разбит на модули, каждый отвечает за своё:

| Файл                 | Ответственность                                                                                                                         |
| -------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| `lesson_times.py`    | Расчёт времени пар по дню недели. API колледжа не отдаёт время — считаем сами: Пн сдвинут на 30 мин, Сб пары по часу, Вс — выходной.    |
| `schedule_api.py`    | Клиент API колледжа. Единственное место, которое знает про HTTP, URL и JSON. Ретраи, таймауты, нормализация, поиск группы.              |
| `database.py`        | SQLite: настройки, снимки расписания, объявленные недели, кэш справочников, лог уведомлений, PNG недель. WAL-режим, потокобезопасность. |
| `comparator.py`      | Сравнение двух снимков. Список изменений, определение «массовости» (когда слать полное расписание).                                     |
| `renderer.py`        | Рендер PNG: таблица дня (колонка «Пара» + одна колонка дня) и таблица недели (Пн–Сб). Подсветка изменений, теги СП, сокращение ФИО.     |
| `vk_upload.py`       | Загрузка PNG в VK (`photos.getMessagesUploadServer` → `photos.saveMessagesPhoto`). Возвращает attachment.                               |
| `schedule_sender.py` | Общий хелпер: превращает `ScheduleMessage` в отправленный в ВК пост (рендер → upload → send), с fallback на текст при ошибках.          |
| `formatter.py`       | Формирование текстов для fallback: расписание дня, недели, короткий diff, полное расписание при массовых изменениях.                    |
| `scheduler.py`       | Планировщик: когда и что проверять. Логика окон по дням недели, объявление недели, группировка изменений.                               |
| `handlers.py`        | Команды бота: `/start`, `/group`, `/today` и т.д. Проверка прав админа.                                                                 |
| `command_guard.py`   | Защита от спама команд (кулдаун + отмена предыдущей). Отключён в handlers — см. «Особенности работы».                                   |
| `config.py`          | Загрузка переменных окружения из `.env`. Список админов, ID группы, TZ.                                                                 |
| `bot.py`             | Точка входа: long-polling ВК + фоновый цикл проверки в одном asyncio-loop. Приветствие при первом запуске.                              |

## Папка assets/

Сюда положи три TTF-шрифта (должны лежать в репозитории — `.gitignore`
их не трогает):

- `NotoSans-Regular.ttf` — основной текст;
- `NotoSans-Bold.ttf` — заголовки, номера пар, названия дисциплин;
- `NotoEmoji-Regular.ttf` — колокольчик 🔔 у изменённых пар.

Скачать:

- NotoSans: https://fonts.google.com/noto/specimen/Noto+Sans
- NotoEmoji (монохромный): https://fonts.google.com/noto/specimen/Noto+Emoji

Если шрифтов нет — `renderer.py` падает в fallback `ImageFont.load_default()`
и пишет warning в лог. Тесты не падают — картинка рисуется, но без кириллицы.

## Установка

### 1. Создайте сообщество ВК

1. Откройте https://vk.com/groups и создайте сообщество (тип — любой).
2. Управление → Работа с API → Создать ключ.
3. Дайте права: **«Управление сообществом»**, **«Сообщения сообщества»**,
   **«Фотографии сообщества»**.
4. Включите **Long Poll API** в той же вкладке.
5. В **«Типы событий»** отметьте **«Входящие сообщения»**.
6. Скопируйте токен вида `vk1.a.xxxxxx`.
7. Запомните ID сообщества (число из `vk.com/clubXXXXXXXX`) —
   понадобится как `VK_GROUP_ID`.

### 2. Клонируйте репозиторий

```bash
git clone https://github.com/spkh-design/Syllabus.git
cd Syllabus
```

### 3. Создайте `.env`

```bash
cp .env.example .env
```

Заполните:

- `VK_TOKEN` — токен из шага 1;
- `VK_GROUP_ID` — ID вашего сообщества;
- `ADMIN_USER_IDS` — ваш VK user ID (узнать можно командой `/whoami` у бота);
- `ADMIN_PEER_ID` — ID чата для служебных сообщений (опционально).

### 4. Установите зависимости

```bash
pip install -r requirements.txt
```

### 5. Положите шрифты в `assets/`

См. раздел [Папка assets/](#папка-assets).

### 6. Запустите

```bash
python bot.py
```

Бот начнёт long-polling и фоновый цикл проверки.

## Команды бота

### Публичные

| Команда     | Что делает                                  |
| ----------- | ------------------------------------------- |
| `/start`    | Приветствие + краткая инструкция            |
| `/help`     | То же, что `/start`                         |
| `/where`    | Какая группа сейчас отслеживается           |
| `/today`    | Расписание на сегодня (PNG)                 |
| `/tomorrow` | Расписание на завтра (PNG)                  |
| `/week`     | Расписание на текущую неделю (PNG, Пн–Сб)   |
| `/nextweek` | Расписание на следующую неделю (PNG, Пн–Сб) |
| `/whoami`   | Показать свой `from_id`, `peer_id`, статус  |

### Админские (только для `ADMIN_USER_IDS`)

| Команда                   | Что делает                                           |
| ------------------------- | ---------------------------------------------------- |
| `/group СП-N №группы`     | Задать группу и подразделение                        |
| `/interval N`             | Изменить интервал проверки (минуты, 5–1440)          |
| `/status`                 | Что настроено, когда последняя проверка              |
| `/test`                   | Тестовое уведомление + расписание на сегодня         |
| `/metrics`                | Счётчики проверок/уведомлений/ошибок                 |
| `/subscribers`            | Кто получает уведомления                             |
| `/week_skip [DD.MM.YYYY]` | Пометить неделю как «объявленную» (без автоотправки) |
| `/unsubscribe`            | Сбросить настройки (отписаться)                      |

`on_unknown` реагирует только на текст, начинающийся с `/`. На «привет»,
«как дела», эмодзи — молчит.

## Расписание проверок

Планировщик (`scheduler.should_check_now`) определяет, какие даты проверять
в текущий момент:

| День  | Время       | Что проверяет                |
| ----- | ----------- | ---------------------------- |
| Пн–Пт | 06:30–17:00 | Сегодня                      |
| Пн–Пт | 14:30–23:00 | Завтра                       |
| Пт    | 14:00–23:00 | Вся следующая неделя (Пн–Вс) |
| Сб    | 08:00–23:00 | Вся следующая неделя         |
| Вс    | 08:00–23:00 | Вся следующая неделя         |
| Вс    | 14:30–23:00 | Завтра (= понедельник)       |

Интервалы перекрываются — за один цикл может проверяться несколько дат.
Реальный интервал между циклами задаётся `CHECK_INTERVAL_MINUTES`
(по умолчанию 30 мин).

## Особенности работы

- **Массовые изменения.** Если изменилось >50% пар дня (и их ≥3),
  или одинаковое изменение у ≥3 пар подряд — шлётся полное расписание
  дня/недели с подсветкой.
- **Три и более дней недели изменились** → одна картинка всей недели.
  Меньше → по одной картинке на изменившийся день.
- **«Самостоятельная работа».** Переходы СР → Дистант → СР-1 и т.п.
  не считаются изменением (см. `SELF_STUDY_AUDITORIA` в `comparator.py`).
- **Пары после последнего занятия** на сегодня не отправляются —
  снимок обновляется, но уведомление не уходит.
- **Автообъявление недели.** Как только колледж выкладывает расписание
  следующей недели (≥3 дней с парами или воскресенье ≥13:00),
  бот один раз отправляет его картинкой и ставит флаг в БД.
- **Первая неделя семестра** (1–7 сентября, 8–14 января) не объявляется
  автоматически — работаем по дням.
- **Защита от спама (`command_guard.py`)** — модуль написан и покрыт
  тестами, но не подключён в `handlers.py`. Включается отдельным патчем.
- **TZ.** На Bothost используется `Asia/Yekaterinburg` из env. На Windows
  `TZ` игнорируется, но timestamp'ы API оборачиваются в фиксированную
  зону (`SCHEDULE_TZ` в `schedule_api.py`), поэтому сдвига дат нет.

## Развёртывание в облаке

Пример для Bothost:

1. Подключите GitHub-репозиторий к Bothost.
2. В панели Bothost задайте переменные окружения:

   ```
   VK_TOKEN=vk1.a.xxxxx
   VK_GROUP_ID=xxxxxxxxx
   ADMIN_USER_IDS=xxxxxxxxx
   ADMIN_PEER_ID=xxxxxxxxx
   TZ=Asia/Yekaterinburg
   DB_PATH=/app/data/bot.db
   CHECK_INTERVAL_MINUTES=30
   COMMAND_COOLDOWN_SECONDS=6
   ```

3. Смонтируйте постоянный volume на `/app/data/` — там лежит БД
   и кэш PNG недель.
4. `git push` → Bothost пересоберёт контейнер и перезапустит бота.

`Dockerfile` в репозитории использует `python:3.13-slim`, ставит
зависимости из `requirements.txt`, копирует код и папку `assets/`.

## Как адаптировать под другой колледж

Основные точки:

1. **`schedule_api.py`** — URL'ы и парсинг JSON API. Меняются `BASE_URL`,
   `INDEX_ENDPOINT`, `SCHEDULE_ENDPOINT`, `HEADERS`, `SCHEDULE_TZ`.
2. **`lesson_times.py`** — расписание звонков (`_LESSON_DURATION`,
   `_FIRST_LESSON_START`, `_LUNCH_BREAK`).
3. **`formatter.py`** — `WEEKDAYS_RU`, формат заголовков.
4. **`renderer.py`** — палитра (`COLOR_*`), размеры (`WEEK_WIDTH`,
   `DAY_WIDTH`), теги СП (`_TAGS`).
5. **`config.py`** — список админов и ID сообщества.

Общая логика (БД, планировщик, comparator, дедупликация, фоновый цикл)
не зависит от конкретного колледжа.

## Разработка и тесты

```bash
pytest -v                # все тесты
pytest -m smoke -v       # только smoke (реальный API, вручную)
pytest test_scheduler.py -v # вместо test_scheduler.py любой другой файл с тестами
```

Тесты не ходят в сеть — HTTP замокан. `test_smoke.py` запускается
только вручную (`pytest -m smoke`).
