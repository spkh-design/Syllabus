# 🎓 Бот расписания СПК

VK-бот, который следит за изменениями расписания Сургутского
политехнического колледжа и присылает уведомления в беседы групп
и преподавателей. Один экземпляр бота обслуживает **несколько бесед**
одновременно (multi-tenant).

Умеет:

- следить за расписанием каждой подключённой **группы** и **преподавателя**
  в автоматическом режиме;
- присылать изображение с таблицей расписания (как на сайте колледжа)
  для `/today`, `/tomorrow`, `/week`, `/nextweek`;
- присылать короткие уведомления об изменениях (замена преподавателя,
  кабинета, отмена пары, дистант) с подсветкой изменённых пар;
- при массовых изменениях — присылать полное расписание дня или всей недели;
- автоматически отправлять расписание следующей недели, как только
  колледж его выложит;
- **распознавать расписания звонков** в сообщениях куратора (текст + фото
  через OCR) и переотправлять их в чат перед нужной датой;
- **пинговать куратора**, если перед праздником не выложено расписание звонков;
- показывать сохранённое расписание звонков вручную через `/bell`;
- **управлять контактами** преподавателей и студентов (добавлять, обновлять, удалять) локально для
  каждой беседы;
  - **искать преподавателя** (`/where_is Фамилия`), чтобы узнать, где он сейчас находится или когда у него следующая пара;
- работать автономно 24/7 в облаке.

## Как это работает

Бот обращается к двум эндпоинтам сайта колледжа:

- `/api/schedule/index` — справочники (группы, преподаватели,
  дисциплины, аудитории);
- `/api/schedule/schedule?date=<timestamp>` — расписание на дату.

Справочники кэшируются в SQLite на сутки. Расписание проверяется
по расписанию окон (см. [Расписание проверок](#расписание-проверок)),
сравнивается с предыдущим снимком в БД. Если что-то изменилось —
формируется изображение с таблицей расписания и отправляется в беседу ВК.

Изображение рисуется локально (Pillow), без внешних сервисов.
Хранится только PNG недели (для дедупликации); дневные PNG создаются
на лету и удаляются после отправки.

Параллельно бот читает **все входящие сообщения** во всех подключённых
беседах через Long Poll. Если в сообщении есть слово «звонк…» и дата —
оно сохраняется как расписание звонков. Текст распознаётся как напрямую,
так и через OCR (Tesseract) из приложенной картинки. В день перед
указанной датой (после 18:00) бот переотправляет это расписание в чат.
Если расписание не появилось и на следующий день — праздник, бот
пингует куратора группы.

Данные хранятся в SQLite в режиме `journal_mode=delete` — все записи
сразу пишутся в основной файл `bot.db`. Это надёжнее при деплое
в контейнерах, где WAL-файл может не пережить пересборку.

## Архитектура

Проект разбит на модули, каждый отвечает за своё:

| Файл                 | Ответственность                                                                                                                                                |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `lesson_times.py`    | Расчёт времени пар по дню недели. API колледжа не отдаёт время — считаем сами: Пн сдвинут на 30 мин, Сб пары по часу, Вс — выходной.                           |
| `schedule_api.py`    | Клиент API колледжа. Единственное место, которое знает про HTTP, URL и JSON. Ретраи, таймауты, нормализация, поиск группы.                                     |
| `contact_parser.py`  | Парсер строк для команд управления контактами (разбирает `Почта: ... Телефон: ...`).                                                                           |
| `database.py`        | SQLite: настройки, снимки, группы, преподаватели, контакты преподавателей и студентов, bell schedules и т.д.                                                   |
| `command_guard.py`   | Защита от спама команд (кулдаун + отмена предыдущей). Подключён через декоратор `@guarded` в `bot.py`.                                                         |
| `comparator.py`      | Сравнение двух снимков. Список изменений, определение «массовости» (когда слать полное расписание).                                                            |
| `renderer.py`        | Рендер PNG: таблица дня и таблица недели (Пн–Сб). Подсветка изменений, теги СП, сокращение ФИО.                                                                |
| `vk_upload.py`       | Загрузка PNG в VK (`photos.getMessagesUploadServer` → `photos.saveMessagesPhoto`). Скачивание фото по URL.                                                     |
| `schedule_sender.py` | Хелпер отправки `ScheduleMessage` в ВК: рендер → upload → send, с fallback на текст.                                                                           |
| `formatter.py`       | Формирование текстов (fallback): расписание дня, недели, короткий diff, полное расписание при массовых изменениях.                                             |
| `scheduler.py`       | Планировщик: когда и что проверять. Логика окон по дням недели, объявление недели, группировка изменений.                                                      |
| `handlers.py`        | Команды бота: `/start`, `/group`, `/add_group`, `/teacher`, `/add_teacher`, `/today`, `/bell`, `/where_is`, `/contact` и т.д. Проверка прав админа.            |
| `group_resolver.py`  | Определение, к какой группе относится команда — из беседы или из ЛС (по `peer=N` или через `/use`).                                                            |
| `bell_detector.py`   | Детектор расписаний звонков. Понимает списки дат (через переносы строк или запятые), текстовые триггеры («пары по часу», «без обеда») и игнорирует «выходные». |
| `bell_sender.py`     | Логика отправки bell schedules в 18:00. Отправка или пинг куратора. Подмешивает кастомный текст (например, «пары по часу»), если он был сохранён.              |
| `holidays.py`        | Загрузка списка праздников из `holidays.json` (yearly + specific).                                                                                             |
| `ocr.py`             | OCR через Tesseract: препроцессинг картинки (Pillow) + распознавание (3 PSM).                                                                                  |
| `config.py`          | Загрузка переменных окружения из `.env`. Список админов, ID сообщества, TZ.                                                                                    |
| `bot.py`             | Точка входа: long-polling ВК + фоновый цикл. Приём всех сообщений через `raw_event`. Приветствие при первом запуске.                                           |

## Папка assets/

Сюда положи три TTF-шрифта (должны лежать в репозитории — `.gitignore` их не трогает):

- `NotoSans-Regular.ttf` — основной текст;
- `NotoSans-Bold.ttf` — заголовки, номера пар, названия дисциплин;
- `NotoEmoji-Regular.ttf` — колокольчик 🔔 у изменённых пар.

Скачать:

- NotoSans: https://fonts.google.com/noto/specimen/Noto+Sans
- NotoEmoji (монохромный): https://fonts.google.com/noto/specimen/Noto+Emoji

⚠️ Не добавляйте `*.ttf` в `.gitignore`. Шрифты должны лежать в репозитории — при сборке Docker-образа они копируются в `/app/assets/`. Если их не будет, `renderer.py` упадёт в fallback `load_default()`, и в PNG не будет кириллицы.

## Установка

### 1. Создайте сообщество ВК

1. Откройте https://vk.com/groups и создайте сообщество (тип — любой).
2. Управление → Работа с API → Создать ключ.
3. Дайте права: **«Управление сообществом»**, **«Сообщения сообщества»**,
   **«Фотографии сообщества»**.
4. Включите **Long Poll API** в той же вкладке.
5. В **«Типы событий»** отметьте **все события в разделе «Сообщения»**
   (входящие, исходящие, изменения). Без этого бот не увидит обычные
   сообщения в беседах.
6. Скопируйте токен вида `vk1.a.xxxxxx`.
7. Запомните ID сообщества (число из `vk.com/clubXXXXXXXX`) —
   понадобится как `VK_GROUP_ID`.

**Важно:** бот должен быть **администратором** в тех беседах, где он
работает. Иначе VK не отдаёт ему события обычных сообщений (только
команды с `/`).

### 2. Клонируйте репозиторий

```bash
git clone https://github.com/spkh-design/Syllabus.git
cd Syllabus
```

### 3. Создайте `.env`

```bash
cp .env.example .env
```

Заполните:

- `VK_TOKEN` — токен из шага 1;
- `VK_GROUP_ID` — ID вашего сообщества;
- `ADMIN_USER_IDS` — VK user ID администраторов (узнать командой `/whoami`);
- `ADMIN_PEER_ID` — ID чата для служебных сообщений (опционально).

⚠️ Если ADMIN_USER_IDS пусто — ни одна админ-команда работать не будет. Это не «потом настроим» — это блокер. Свой ID можно узнать, написав боту /whoami в ЛС или в беседе с любого другого аккаунта (или из-под себя, если ты уже там).

### 4. Установите зависимости

```bash
pip install -r requirements.txt
```

### 5. Установите Tesseract (для OCR)

OCR нужен, чтобы распознавать расписания звонков, которые куратор
присылает картинкой без подписи.

**Ubuntu / Debian (в том числе Docker):**

```bash
sudo apt-get install tesseract-ocr tesseract-ocr-rus
```

**macOS (Homebrew):**

```bash
brew install tesseract tesseract-lang
```

**Windows:**

1. Скачайте installer: https://github.com/UB-Mannheim/tesseract/wiki
2. При установке отметьте галочку **Russian** в разделе
   Additional language data.
3. Установите в `C:\Program Files\Tesseract-OCR\` (по умолчанию).
4. `ocr.py` найдёт его автоматически по стандартному пути, если
   Tesseract не в `PATH`. Либо задайте переменную окружения
   `TESSERACT_CMD=C:\path\to\tesseract.exe`.

Проверка:

```bash
tesseract --version
```

Должна появиться строка вида `tesseract 5.x.x`.

Если OCR недоступен — бот продолжит работать, но детекция расписаний
звонков по фото не будет работать (только по тексту). В логе будет
предупреждение `Tesseract недоступен — OCR отключён`.

### 6. Положите шрифты в `assets/`

См. раздел [Папка assets/](#папка-assets).

### 7. Настройте праздники

Отредактируйте `holidays.json` в корне проекта — список праздников,
перед которыми бот ждёт расписание звонков от куратора:

```json
{
  "yearly": [
    { "date": "02-23", "name": "День защитника Отечества" },
    { "date": "03-08", "name": "Международный женский день" },
    { "date": "05-01", "name": "Праздник весны и труда" },
    { "date": "05-09", "name": "День Победы" },
    { "date": "10-05", "name": "День учителя" }
  ],
  "specific": []
}
```

`yearly` — повторяются каждый год (формат `MM-DD`).
`specific` — разовые даты (формат `YYYY-MM-DD`).

### 8. Запустите

```bash
python bot.py
```

Бот начнёт long-polling и фоновый цикл проверки.

### 9. Настройте первую группу или преподавателя

В беседе, куда добавлен бот, для группы:

```
/add_group СП-X yyy
```

Для преподавателя:

```
/teacher Фамилия Имя Отчество
```

Или из личных сообщений, если знаете `peer_id` беседы:

```
/add_group peer=2000000000 СП-X yyy
/add_teacher peer=2000000000 Фамилия Имя Отчество
```

### 10. Назначьте куратора для пингов в праздники (только для групп)

В той же беседе:

```
/set_curator <VK-ID>
```

или

```
/set_curator @username
```

### Команда `/bell` — расписание звонков на дату

```
/bell 21.10.26
/bell 21.10.2026
/bell 21 октября
/bell 21 октября 2026
/bell 21.10.26 peer=2000000002    (из ЛС)
```

Возможные ответы:

- **Есть сохранённое расписание с картинкой** → бот присылает
  `🔔 Расписание звонков на 21.10.26` + изображение.
- **Есть запись, но без картинки** (куратор прислал текстом) → бот
  присылает `Расписание звонков на 21.10.26.` + текст сообщения куратора.
- **Записи нет** → `📅 Расписание звонков на 21.10.26. Без изменений — обычное расписание.`
- **Дата в прошлом** → `⚠️ День уже прошёл.`
- **Больше 30 дней вперёд** → `❌ Слишком далеко. Максимум — 30 дней вперёд.`
- **Дата не распознана** → подсказка с форматами.

`on_unknown` реагирует только на текст, начинающийся с `/`. На «привет»,
«как дела», эмодзи — молчит.

### Управление контактами

Бот позволяет вести базу контактов преподавателей и студентов. Контакты **локальны для каждой беседы** — то есть в одной группе они свои, в другой — свои. Это сделано для того, чтобы студенты не видели лишнюю информацию.

Добавление и обновление происходит через единый синтаксис `Ключ: Значение`.
Доступные ключи: `Почта`, `Телефон`, `Телеграмм`, `Группа телеграмм`, `ВК`, `ВК группа`, `Папки`, `Ссылка MAX`, `Адрес`.

Примеры:

```
/add_contact Дубров Никита Александрович Почта: nikita@mail.ru Телефон: +79991112233
/add_student_contact Иванов Иван Почта: ivan@mail.ru Адрес: г. Сургут, ул. Ленина 1
```

Если полей несколько, их можно перечислять через запятую: `Телефон: 123, 456`.

### Клавиатуры (кнопки)

Бот использует два типа клавиатур, доступных в VK API. Выбор типа зависит от того, где находится пользователь:

- **В личных сообщениях (ЛС)** по команде `/start` появляется **Reply-клавиатура** (снизу экрана). Она
  остаётся висеть над полем ввода.
  - _Особенность VK:_ в Reply-клавиатурах запрещены Callback-кнопки, поэтому нажатие на них просто отправляет текст кнопки в чат (например, «Сегодня»). Бот перехватывает этот текст и выполняет соответствующую команду.
- **В беседах** Reply-клавиатуры недоступны (ограничение VK), поэтому по команде `/help` бот присылает
  сообщение с **Inline-кнопками** (прикреплёнными прямо под сообщением).
  - _Особенность VK:_ Inline-кнопки используют скрытый `payload` и срабатывают мгновенно, не отправляя лишний текст в чат.
  - _Ограничение VK:_ максимальное количество кнопок в Inline-клавиатуре — 10 штук. Поэтому в админское меню `/help` добавлены только самые важные функции.

**Доступные кнопки:**

- **Публичные (для всех):** `Сегодня`, `Завтра`, `Неделя`, `След.`, `Звонки`, `Где я`, `Контакты`,
  `Студенты`.
- **Админские (в ЛС):** `Статус`, `Группы`, `Преподаватели`, `Добавить группу`, `Добавить препода`,
  `Добавить студента`, `Интервал`, `Пропустить неделю`, .
- **Админские (в беседах):** `+ Препод`, `+ Студент`, `Стоп` (отписка).

Команды, требующие аргументов (например, `/add_contact`, `/interval`, `/add_group`), при нажатии на кнопку отправляют боту команду без аргументов. Бот в ответ присылает подсказку с правильным форматом, и пользователь может просто дописать нужный текст.

## Расписание проверок

Планировщик (`scheduler.should_check_now`) определяет, какие даты проверять
в текущий момент:

| День  | Время       | Что проверяет                |
| ----- | ----------- | ---------------------------- |
| Пн–Пт | 06:30–17:00 | Сегодня                      |
| Пн–Пт | 14:30–23:00 | Завтра                       |
| Пт    | 14:00–23:00 | Вся следующая неделя (Пн–Вс) |
| Сб    | 08:00–23:00 | Вся следующая неделя         |
| Вс    | 08:00–23:00 | Вся следующая неделя         |
| Вс    | 14:30–23:00 | Завтра (= понедельник)       |

Интервалы перекрываются — за один цикл может проверяться несколько дат.
Реальный интервал между циклами задаётся `CHECK_INTERVAL_MINUTES`
(по умолчанию 30 мин).

## Расписания звонков

Бот автоматически распознаёт расписания звонков, которые куратор
присылает в беседу. Работает по тексту и по картинке:

1. Каждое входящее сообщение сохраняется в `chat_messages`.
2. Если в тексте есть «звонк…» **и** дата в пределах ±200 символов —
   сообщение фиксируется как расписание звонков.
3. Если приложена картинка — она скачивается, прогоняется через
   Tesseract (3 режима PSM), OCR-текст объединяется с текстом сообщения
   и тоже участвует в детекции.
4. Найденное расписание сохраняется в `bell_schedules` (UPSERT по
   `(peer_id, target_date)` — свежая версия вытесняет старую).

Стоит помнить, что бот читает только те сообщения, что приходят после его добавления в беседу и выдачи админ-прав. Сообщения из истории (до установки) он не увидит — VK их не отдаёт через Long Poll. Если нужно проанализировать старые расписания звонков — попросите куратора прислать их повторно.

### Отправка в чат

Каждый день после **18:00** бот для каждой активной группы смотрит,
есть ли расписание звонков на завтра:

- **Найдено, прислано сегодня** → не отправляем (куратор только что написал).
- **Найдено, прислано вчера** → отправляем, только если в чате
  с момента появления записи было **больше 10 сообщений** (иначе все
  помнят свежую инфу). Меньше — тишина.
- **Найдено, прислано позавчера и раньше** → отправляем.
- **Найдено и уже отправлено** → не повторяем.
- **Не найдено, но завтра праздник** → **пингуем куратора** один раз:
  `🔔 Завтра 05.10 — День учителя. [id123|Имя], проверьте, пожалуйста, расписание звонков на наличие изменений.`
- **Не найдено, завтра не праздник** → тишина.
- Если у расписания есть **кастомный текст** (например, «пары по часу, 2 обеда»), бот отправит его
  вместе с напоминанием:
  `🔔 Напоминаем: расписание звонков на 03.11 (завтра):`
  `пары по часу, 2 обеда`

Флаг «проверка уже была сегодня» хранится в `settings['bell_check_date']`.
Флаг «куратора пинговали по этой дате» — в таблице `holiday_pings`.

### Очистка

- Изменения в `holidays.json` подхватываются только после перезапуска бота. Если добавили новый праздник
  — перезапустите контейнер (или подождите следующей пересборки на Bothost).
- Записи `bell_schedules` удаляются через сутки после `target_date`
  (`cleanup_old_bell_schedules`).
- Флаги `holiday_pings` — старше 30 дней.
- Сообщения `chat_messages` — старше 30 дней.

## Особенности работы

- **Массовые изменения.** Если изменилось >50% пар дня (и их ≥3),
  или одинаковое изменение у ≥3 пар подряд — шлётся полное расписание
  дня/недели с подсветкой.
- **Отправка изображений.** При отправке нескольких картинок подряд VK может ответить photo='', HTTP 405
  или 504. У бота есть 4 попытки с backoff 3/6/9 секунд. Обычно второй-третий запрос проходит. В логе
  увидите VK отверг PNG (попытка N/4) — это нормально, не пугайтесь.
- **Три и более дней недели изменились** → одна картинка всей недели.
  Меньше → по одной картинке на изменившийся день.
- **«Самостоятельная работа».** Переходы СР → Дистант → СР-1 и т.п.
  не считаются изменением (см. `SELF_STUDY_AUDITORIA` в `comparator.py`).
- **Пары после последнего занятия** на сегодня не отправляются —
  снимок обновляется, но уведомление не уходит.
- **Автообъявление недели.** Как только колледж выкладывает расписание
  следующей недели (≥3 дней с парами или воскресенье ≥13:00),
  бот один раз отправляет его картинкой и ставит флаг в БД.
- **Первая неделя семестра** (1–7 сентября, 8–14 января) не объявляется
  автоматически — работаем по дням.
- **Multi-tenant.** Один экземпляр бота обслуживает несколько бесед.
  В каждой — либо своя группа (с куратором), либо свой преподаватель.
  Списки хранятся в таблицах `groups` и `teachers`.
- **Взаимоисключение.** Беседа не может быть одновременно и группой, и преподавателем.
  Если в чате группы вызвать `/teacher`, группа перезапишется на преподавателя, и наоборот.
- **Heartbeat.** В логах фонового цикла каждые N минут пишется
  `>>> checker: цикл завершен, heartbeat OK`. Это помогает понять, что бот жив, даже если изменений нет.
- **Приём всех сообщений.** Бот читает все входящие через `raw_event`
  (низкий уровень vkbottle). Для этого он должен быть **администратором**
  в беседе — без админ-прав VK не отдаёт события обычных сообщений.
- **Защита от спама (command_guard.py).** Включена через декоратор @guarded. Кулдаун по умолчанию — 6
  секунд (настраивается через COMMAND_COOLDOWN_SECONDS). Команда /whoami исключена из кулдауна.
- **TZ.** На Bothost используется `Asia/Yekaterinburg` из env. На Windows
  `TZ` игнорируется, но timestamp'ы API оборачиваются в фиксированную
  зону (`SCHEDULE_TZ` в `schedule_api.py`), поэтому сдвига дат нет.

## Развёртывание в облаке

Пример для Bothost:

1. Подключите GitHub-репозиторий к Bothost.
2. В панели Bothost задайте переменные окружения:

   ```
   VK_TOKEN=vk1.a.xxxxx
   VK_GROUP_ID=ggggggggg
   ADMIN_USER_IDS=xxxxxxxxx,yyyyyyyyy
   ADMIN_PEER_ID=xxxxxxxxx
   TZ=Asia/Yekaterinburg
   DB_PATH=/app/data/bot.db
   CHECK_INTERVAL_MINUTES=30
   COMMAND_COOLDOWN_SECONDS=6
   ```

3. Смонтируйте постоянный volume на `/app/data/` — там лежат БД,
   кэш PNG недель и расписания звонков. Без volume настройки будут
   сбрасываться при пересборке контейнера.
4. В панели Bothost проверьте, что **тариф** позволяет постоянное
   хранилище. На тарифе Basic volume может быть недоступен.
5. `git push` → Bothost пересоберёт контейнер и перезапустит бота.

`Dockerfile` в репозитории использует `python:3.13-slim`, ставит
зависимости из `requirements.txt`, устанавливает Tesseract с русским
языком, копирует код, `holidays.json` и папку `assets/`.

**Особенности Docker-образа:**

- `PYTHONUNBUFFERED=1` — логи видны сразу, без буферизации.
- `DB_PATH=/app/data/bot.db` — по умолчанию.
- Volume `/app/data` — объявлен через `VOLUME`.

## Как адаптировать под другой колледж

Основные точки:

1. **`schedule_api.py`** — URL'ы и парсинг JSON API. Меняются `BASE_URL`,
   `INDEX_ENDPOINT`, `SCHEDULE_ENDPOINT`, `HEADERS`, `SCHEDULE_TZ`.
2. **`lesson_times.py`** — расписание звонков (`_LESSON_DURATION`,
   `_FIRST_LESSON_START`, `_LUNCH_BREAK`).
3. **`formatter.py`** — `WEEKDAYS_RU`, формат заголовков.
4. **`renderer.py`** — палитра (`COLOR_*`), размеры (`WEEK_WIDTH`,
   `DAY_WIDTH`), теги СП (`_TAGS`).
5. **`bell_detector.py`** — триггеры «звонк…» и месяцы (`_MONTHS_RU`).
6. **`holidays.json`** — список праздников.
7. **`config.py`** — список админов и ID сообщества.

Общая логика (БД, планировщик, comparator, дедупликация, фоновый цикл,
multi-tenant, OCR) не зависит от конкретного колледжа.

## Разработка и тесты

```bash
pytest -v                    # все тесты
pytest -m smoke -v           # только smoke (реальный API, вручную)
pytest test_scheduler.py -v  # конкретный модуль
```

Тесты не ходят в сеть — HTTP замокан. `test_smoke.py` запускается
только вручную (`pytest -m smoke`). Tesseract в тестах тоже мокается —
их можно запускать без установленного OCR.

Также не запускайте два экземпляра бота с одним VK_TOKEN. Long Poll привязывается к токену, и второй экземпляр будет воровать события у первого. Останавливайте прод-версию, прежде чем запускать локальную.

### Диагностика

Если изображение не загружается в VK:

- в логах искать `VK upload-server response keys: ...` и
  `VK не принял файл ...`.

Если bell schedules не детектятся:

- проверить, что `tesseract --version` работает.
